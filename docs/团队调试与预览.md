# 团队调试与预览

产品根入口采用团队最新 Horizon 页面，内部工作台位于 `/workbench.html`。同一前端提供演示与真实模式；完整应用使用同源后端，静态构建永久禁用真实模式。

| 能力 | 静态演示 | 完整应用 |
|---|---|---|
| 首页/对话/指南/分享 | 最新团队页面与虚构对话 | 同一页面，真实登录与 SDK 问答 |
| 记忆 | 虚构浏览器记录 | 自动整理、主题摘要、来源查看与删除 |
| 历史 | 浏览器演示记录 | 当前浏览器按账号隔离的会话存储，无跨设备历史 API |
| 环节/整体评测 | 不打包 | 需账号，使用隔离测试数据及真实模型额度 |

完整启动按 [README](../README.md) 与[部署手册](Agent部署与验收.md)。推荐用合成输入检查：登录 → 查看自动记忆说明 → 问手机通知困扰 → 查看指南正文与保存状态 → 打开我的记忆展开来源 → 继续同主题 → 删除来源或主题 → 确认回访和理解不残留已删内容 → 切换账号验证隔离。单独验证删除对话使 SDK 恢复失效。

工作台先选一个环节，使用样例输入运行当前提示词，再编辑草稿观察契约校验和输出；随后用整体交互和批量 A/B 验证真实完整流程。自动格式通过不代表内容质量通过，记录人工判断与证据。

静态预览：

```sh
python scripts/build_preview.py
python -m http.server 8790 --bind 127.0.0.1 --directory .preview-site
```

打开 `http://127.0.0.1:8790`。构建不会读取模型配置、运行数据库或账号。不能用静态演示验收登录安全、模型检索、记忆持久化或 SDK 恢复。

常规更新沿用原 Compose 项目名与数据卷，执行 `docker compose --env-file .env.compose up -d --build`。产品旧关闭状态在新版本启动时迁移为自动记忆；不删除已有来源。提示词初始 Markdown 修改不会覆盖已部署版本，应在工作台保存版本、测试组合，再显式启用。不要删除数据卷。失败时只报告脱敏状态码/错误，不把密钥、Cookie 或个人原话提交到 Issue。
