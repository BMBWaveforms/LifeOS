# 团队调试与预览

用 Agent 操作时，先读 [AGENTS.md](../AGENTS.md) 和 [Agent 部署与验收手册](Agent部署与验收.md)。完整部署、静态预览和真实模型验收的完成条件分别列在手册中。

## 选择体验方式

无服务器时，先用 GitHub Pages 看界面和交互，再在团队成员各自电脑用 Docker 跑真实问答。页面上“静态预览”和“模拟摘要”的标记区分了两种体验。

| 能力 | 在线静态预览 | 完整 Docker 应用 |
|---|---|---|
| 问答 | 固定的手机通知案例；其他问题提示未接入模型 | Agent 搜索、完整回读、来源校验和回答 |
| 摘要 | 前端模拟记录，有明确标识 | 每轮调用模型生成摘要，校验后写入 SQLite |
| 回访 | 浏览器按模拟记录显示进展和继续咨询按钮 | 后端筛选未解决主题，模型选择记录，再生成回访问题 |
| 记忆管理 | 当前浏览器内纠正、删除、清空、关闭 | 后端校验用户归属、事务与记忆版本 |
| 账号 | 虚构 alice / bob，演示口令 `preview` | 随机生成的真实体验密码，HTTP-only Cookie 登录 |
| 重启后保留 | 同一浏览器的 localStorage | 持久化 Docker 数据卷 |

在线预览没有服务器认证，账号切换只用于展示交互，不是安全隔离。演示口令不对应完整服务密码。不要在预览中输入个人敏感信息。重置仅删除此预览的两个浏览器存储键，不影响完整服务。

## 第一次调试

按根目录 README 配置私有 `api.json`，运行 Compose 并查看首次密码。API Key 通过每个人的配置文件提供，GitHub 不保存它。若使用共用模型账号，由团队在仓库以外分发凭据。

建议走一遍：登录 Alice → 开启自动摘要 → 提问手机通知困扰 → 查看来源与摘要 → 新会话查看回访 → 点击还没解决 → 点击已经解决 → 刷新后确认不再回访 → 切换 Bob 检查数据独立。

再检查关闭记忆、纠正摘要、删除和清空。失败时记录界面状态、API 状态码及脱敏错误，不把 API Key、密码、Cookie 或完整个人会话放进 Issue。

修改前端或 Python 后端后执行 `docker compose up -d --build`。修改 `prompts/` 对后续调用直接生效；修改部署环境变量后重新创建容器。更新不会自动删除数据卷。

## 无 API Key 的自动测试

安装根目录的 `requirements-lock.txt` 和 `requirements-dev.txt` 后运行 `python -m pytest -q`。测试用 FakeModel 验证来源读取、摘要保存、用户隔离、版本变化和失败行为；模型质量仍需要真实调用验证。

## 在自己电脑看静态预览

```sh
python3 scripts/build_preview.py
python3 -m http.server 8790 --bind 127.0.0.1 --directory .preview-site
```

访问 `http://localhost:8790`。生成目录不提交；构建只复制正式前端、模拟适配层、单条固定指南示例和架构讲解文件，不读取 API 配置或运行数据库。

## GitHub Pages

Pages 使用 `.github/workflows/pages.yml` 构建并发布 `.preview-site`。仓库 Settings → Pages → Build and deployment → Source 设为 **GitHub Actions**。发布结果和错误看 Actions 的 `Static team preview`。网站地址为 `https://shuaishuaisylas.github.io/LifeOS/`。

Pages 是静态托管，不运行 Python；真实问答和服务器长期记忆需要另行部署完整应用。这一边界见 [GitHub 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)。

## 提交与评审

从 `main` 创建自己的功能分支，通过 Pull Request 提交，并附复现步骤和测试结果。Issues 可以记录问题；有权限的团队成员可以审阅和推送。仓库所有者按实际成员在 Settings → Collaborators 分配权限，不共享个人 GitHub 密码。

本地工作目录带 Git 的时候，运行 `python3 scripts/check_publish.py` 检查跟踪文件。`.gitignore` 和 `.dockerignore` 排除私有配置、运行数据和环境缓存；示例配置仅含占位值。检查通过是发布辅助措施，提交者仍应检查实际改动。
