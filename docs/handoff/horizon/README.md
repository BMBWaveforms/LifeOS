## 本次交付与基线

目标仓库：`shuaishuaisylas/LifeOS`；核对基线：`633ccba4f4f9245e467be5c03426f00f18f313fb`。该基线已经合入 partner product frontend，具有真实 SDK/native 执行层、团队账号、提示词版本与评测工作台。Horizon 是另一套候选产品前端，不能拿旧独立项目的后端覆盖这些实现。

- 新版代码：`frontend/horizon/`，入口 `/horizon/`，子路由 `#/`、`#/chat`。
- 原产品：`frontend/index.html`，入口 `/`。本次不切换默认首页。
- 内部工具：`/workbench.html` 等现有文件不动，评测/提示词/账号/数据库/模型配置不迁移。
- 不需要 npm 构建。Node 22 用于测试；浏览器直接加载 ES modules。
- 静态预览构建仍保留原首页，额外生成 `/horizon/`，明确禁止真实 API 模式。
- 本次没有服务器部署、数据库迁移、生产账号操作，也没有运行收费模型验收。

本地预览（在仓库根目录执行）：

```sh
python3 scripts/frontend_server.py --port 8892 --backend-port 8781
```

打开 `http://127.0.0.1:8892/horizon/` 即可演示；没有后端时演示仍可用，健康检查失败不阻断它。真实模式需要另行按根 README 启动后端并使用部署者提供的账号；使用8892开发端口时，后端 ALLOWED_ORIGINS 必须明确包含 http://127.0.0.1:8892（使用 localhost 时也需对应加入）。现有默认8780部署不受影响。不要提交密码、token 或模型密钥。

## 接入重点

| 优先级 | 差异 | 接手要求 |
|---|---|---|
| P0 | 新前端自动记忆且只允许删除；现后端默认关闭、允许关闭/纠正 | 先解决策略冲突，再推广。当前真实提交会读取账号记忆状态，关闭时拒绝发起问答并保留输入；不会替用户静默打开记忆。已启用的账号可使用现有 JSON 问答，但服务端仍需落实策略与验收。 |
| P0 | 真实回答仍是一次性 JSON | 流式容器已就绪，演示会分片；服务端未提供 SSE。不要把 SDK 内部事件/思维链直接接进用户页面。 |
| P0 | 历史、草稿与来源跳转主要在浏览器 | 现有 `conversation_id` 能延续后端短期上下文，不能等同可列举、跨设备、永久保存的历史 API。 |
| P1 | 后端有只读指南校验、revision 失效、账号隔离 | 这些规则必须保留；不能用前端关键词演示服务代替真实 Agent。 |
| P1 | 用户理解、项目分组、账本动画、分享卡片是新增表现 | 各自的数据边界见功能矩阵，不能把演示项目当作已经具备项目管理 API。 |

## 文件所有权与改动范围

- 优先在 `frontend/horizon/service.mjs` 做协议映射；`runtime-config.mjs` 仅使用现有 `/health` 做配置发现。原独立服务的 `/app-config` 未迁入。
- 本次新增前端运行模块、8 类前端测试、独立预览复制脚本，以及候选路由的 Nginx MIME/CSP 支持。原服务入口/模型执行层不变。
- 复制了 687 条相同指南正文，使用本仓库 `data/guide.json` 的完整元数据；正文条目与独立前端逐条相同。测试会防止副本漂移。指南来源/许可、样片来源均随代码附带。
- 独立前端原来的 Python 后端、提示词、虚拟环境、运行时数据、用户记录、账号文件与个人截图全部未上传。
- 为融合增加的前端保护：静态预览禁用真实模式；真实问答检查自动记忆状态；删除记忆后清除浏览器里对应的显式 followup ID。其余已有视觉/交互保持原设计。

## 发布与回退

这是可评审、可演示的集成候选，尚非已完成后端融合的上线版本。先保持双入口，完成 P0 接线和验收后，再由产品负责人决定是否把 Horizon 升为 `/`。不要删除原页面或工作台来实现切换。当前回退只需不使用 `/horizon/`；撤回此 PR 的前端/预览改动不会迁移或清空后端数据。根 CI 仍运行原有全部测试，并经已有测试入口加载 Horizon 测试，不需要更改 workflow。
