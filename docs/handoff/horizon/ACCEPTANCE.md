# 验收流程与融合顺序

先在临时环境验证，不使用生产数据。前端演示能跑通不等于真实 Agent 已接入。

## 自动检查

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt -r requirements-dev.txt
.venv/bin/python -m pytest -q
for file in frontend/*.js preview/*.js frontend/horizon/*.mjs; do node --check "$file"; done
node --test tests/*.cjs
.venv/bin/python scripts/build_preview.py
.venv/bin/python scripts/check_publish.py
```

有 Docker 的环境还应运行现有 CI 的合成配置检查，并构建前端容器，实际验收 `/horizon/*.mjs` 的 JavaScript MIME、CSP 下 blob 图片分享、视频 Range/拖动；不要为检查创建或覆盖真实 model-api 配置。CI 已保留现有 Compose 检查。

## 不依赖后端的桌面走查

1. `/horizon/` 默认交互演示：黑白视频、LEVO品牌与固定slogan、15场景切换，无暂停按钮。输入框下方“直接进入 →”进入空会话，不发消息；回首页选视频则按场景自动发问。
2. 输入“我工作时总被手机通知打断，很难集中注意力”，确认流式文本、完整指南、保存回执。补充一轮；上滚阅读时新分片不抢位置，“回到最新”可恢复。
3. 新会话输入“最近想搬家”，看追问；选择租房或自由补充；另开会话测试“暂不补充”，不能擅自认为用户买房。新会话无空标题面包屑。
4. 流式中停止、重试；流式中刷新，应保留部分文本并显示中断，不假装完成或写入迟到记忆。失败后输入保留；中文输入法确认不得误发。
5. 侧栏收起/展开、连续反向点击，标题和正文同步且无右侧白缝。历史超过6条后仍可在“全部对话”全文搜索、定位、重命名、删除。删除当前对话后仍可新聊。
6. 侧栏直接拖动对话，移动超过8px才开始排序，轻微移动仍为点击；邻项让位、落下后刷新顺序保留。聚焦对话后Alt+上下键可移动，Escape或拖出组外取消。项目组与普通对话不跨组移动、不改变当前对话、总数或内容；点击打开不会改变列表位置，无排序/恢复默认按钮。新对话排在自定顺序之前；全部历史仍能搜索。
7. “搬家计划”仅演示分组，3段可读对话，不出现文件夹管理。理解面板引用用户原话且能定位，不把假设/他人情况写成用户事实。
8. 头像进入记忆：搜索、当前/历史、删除、全部删除；取消/Escape 保留筛选/位置。没有关闭/编辑。继续聊回来源；删除来源后继续聊，带准确摘要新建并自动发送；再次访问复用恢复会话。删记忆后不继续携带旧 followup ID。
9. 决策问题中打开账本，观察问题、各项建议、投入、收益、证据与范围自动逐项变清晰，无需滚动触发；没有“直接看全文”入口。印章只露一点时不能播放，完整进入阅读区后才停顿并落章；中途滑走/开弹层后返回能完整播放。没有底部重播/继续聊入口。验证时间计算与切换指南；读完整指南在内部弹层，不跳GitHub。证据/成本/收益字段保留原文，不伪造数据。
10. 分享指南生成 PNG，下载查看完整内容；系统支持文件分享时可调起，取消可重试。卡片不能含问题、聊天原文、记忆或账号。分享不产生公开链接、不向朋友自动发送。
11. 联系我只有占位样式；免责声明存在。1440×900、1280×800、窄桌面及减少动效模式走查；手机布局不属本版要求。
12. 静态目录 `.preview-site/horizon/` 用静态服务打开，真实模式不可选择，不请求 `/health` 或 `/api/*`；演示数据可留在该浏览器，不可误用原产品预览“刷新清空”文案描述它。

## 需要后端一起验收

- 策略：enabled=false 的旧账号在新版不能静默启用或正常发送；enabled=true 的隔离测试账号可JSON问答。先审定服务端强制自动记忆/禁止编辑方案，再验证账号迁移、删除后不复活、只删权利与旧前端兼容。
- 真实模型：明确部署配置、当前 prompt bundle/runtime，验证至少问候、指南命中、无支持、追问、多轮、回访、摘要失败。必须实际调用后才能写“真实问答通过”。没有模型配置就写未验收。
- 隔离/过期：A/B账号内容互不可见，401保留输入；删除记忆/revision改变后无旧上下文泄露；模型或网络失败不伪造保存成功。
- 历史：服务端重启与跨浏览器不会假装能恢复本机原文；持久化完成后验证来源归属、删除原文但保留摘要、来源已失效降级。
- 流式：接入后验证分片重复/乱序/断线、完成/失败、迟到事件、停止后查询、幂等重试、最终card来源校验及只写一次摘要。没有公开流接口时保留JSON降级。
- 回归原 `/` 和工作台：账号、提示词激活、SDK会话恢复/受控压缩、评测集、隔离会话及数据卷完整。不修改生产服务器或清数据库来“跑通”。

融合顺序：JSON适配与策略 → 来源/持久历史 → 公共流式与操作幂等 → 真实项目/理解字段映射 → 双入口验收 → 负责人决定首页切换。每项分别记录完成和剩余限制。

回答排版：打开“搬家计划 → 搬家前要准备什么”，确认三个18px分节标题、重点加粗、编号/圆点列表和结尾引用；打开“先理清搬家的需求”的后续回复可比较次级标题。发送“我想聊聊通勤”，流式过程中与完成后“拆小一点”均加粗；原始Markdown标记不留在已完成的加粗内容里。普通文本消息与用户原文保持可读。
