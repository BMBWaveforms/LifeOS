# 给接手后端 Agent 的任务

你接手 `shuaishuaisylas/LifeOS` 的 Horizon 前端融合。本轮已同步上游12eb522（统一SDK会话及受控压缩）。先读取根 AGENTS 和本目录全部交接文件；核对当前分支与最新主分支差异，不以这个交接包覆盖更新的主分支。

1. 运行现有测试与 Horizon 测试，打开 `/`、`/workbench.html`、`/horizon/`，建立基线。只使用临时合成数据，除非部署者明确授权操作真实账号。
2. 逐项核对 FEATURE_MATRIX 的 P0 差异，先做现有 JSON API 接线。优先改 Horizon 适配层，保留现有SDK执行层、隔离会话恢复/压缩、全文回读、来源验证、账号隔离、revision 和摘要原子性。
3. 自动记忆策略必须在服务端落实：新前端不提供关闭/编辑入口。先提出兼容老账号/旧前端的明确迁移方案、测试与回退，再实施获授权的数据迁移。不要让前端登录时偷偷调用 settings 开启，不要仅靠隐藏按钮宣称策略完成。
4. 持久历史/来源关系、项目、真实流式、取消/幂等分别实现和验收。上游新增`/api/conversation-action`，候选前端尚未对接；要明确浏览器历史删除与SDK会话撤销的关系。CONTRACT 中“建议”均为未实现协议，不能直接当作已有路由。没有做完时继续保持前端诚实降级。
5. 后端已有 understanding 是任务理解；前端面板是“当前对话中用户明确表达的情况”。先做字段/证据对照再映射，不输出思维链，不把未知条件写成个人事实。
6. 模型运行由当前 registry/部署配置控制。不要把独立原型的 backend、server.py、prompts 或账号文件迁进来；不要提交凭据或运行时数据库。
7. 完成 ACCEPTANCE 并记录真实验收的范围，才能建议把 Horizon 设为默认产品。保持原工作台可用，不把评测会话当作产品聊天历史。

请向下一位 Agent 返回：实际基线 SHA；改动文件与协议版本；逐项 implemented/blocked/deferred；破坏性变化及兼容策略；执行过的测试/结果；真实模型是否实际验收；尚未解决的产品决定；回退办法。不要只回复“已接通”。

常用命令见 ACCEPTANCE。后端接手不意味着需要推翻已确认的视觉：保持黑白、桌面限定、场景直接发问、无文件夹管理、记忆仅删除、内部指南阅读、分享不含私人内容。
