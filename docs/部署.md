# 部署说明

## 保留旧版本

旧版源码、DSL 和原运行数据保持原样。本次未启动旧服务，未修改其配置。新应用独立使用 8780/8781。源码归档在桌面苟活目录的 `保留版本/Dify-v0.2/`，含 SHA-256 校验清单，不含旧运行密钥或个人数据库。

## 本地前后端分离

按照 README 启动，或分别打开两个终端，在 `python-standalone` 目录执行：

```bash
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8781 --workers 1 --no-access-log
```

```bash
.venv/bin/python scripts/frontend_server.py --port 8780 --backend-port 8781
```

后端只提供 JSON API，前端服务只提供 `frontend/` 文件并转发 `/api`，不会提供上一级 `api.json` 或 `.runtime`。两个服务都默认绑定本机回环地址。

首次随机账号密码在 `.runtime/login.json`。查看密码后可将该首次密码文件移到自己的密码管理位置，应用正常登录仅需 `.runtime/auth.json` 的哈希文件。不能只删除 `auth.json` 后继续沿用旧账号密码，因为下次启动会生成新密码。所有运行文件均应作为私有文件管理。

## Docker Compose

项目上一级的 `api.json` 必须存在且非空，或用 `API_CONFIG_PATH` 指定密钥文件路径：

```bash
docker compose up -d --build
docker compose ps
```

前端默认地址 `http://localhost:8780`；后端仅在 Compose 内网监听 8781，外部无法直接连接。登录信息查看命令（输出体验账号密码，不输出模型 API Key）：

```bash
docker compose exec backend python -c 'from pathlib import Path; print(Path("/app/runtime/login.json").read_text())'
```

停止容器用 `docker compose down`，保留记忆卷。再次 `up -d` 后重新登录，摘要仍存在。**不要用 `down -v`，该参数会删除记忆卷。**

本次 Docker 验证为了与本地进程共存，使用独立项目名和 8782：

```bash
WEB_PORT=8782 ALLOWED_ORIGINS=http://localhost:8782,http://127.0.0.1:8782 docker compose -p gouhuo-standalone-demo up -d --build
```

对应登录信息和管理命令需加 `-p gouhuo-standalone-demo`。

模型配置读取 secret 文件，`prompts/` 以只读挂载提供给后端，SQLite 及账号配置保存在命名卷。更新后端或前端代码需要重新构建镜像；修改提示词后后续调用直接读取新文件。修改允许来源或 Cookie 配置后需要重新创建容器。

## 换机及对外部署

1. 复制独立版源码包，另行安全传递 `api.json`，不要将密钥写入前端或镜像。
2. 运行单机 Compose。备份时停止后端后复制整个运行卷，保留账号哈希、数据库和首次凭据文件；恢复时挂到 `memory_data`。
3. 如需对外访问，在同机 HTTPS 网关将正式域名转发至回环地址 8780；设置 `ALLOWED_ORIGINS=https://你的域名` 和 `COOKIE_SECURE=true`。保持后端只在内网访问。
4. 对正式用户开放前替换预置体验账号，补充注册/找回密码/账号管理及所需运维功能。当前提供的是可部署 Demo，不是已完成生产验收的多用户服务。

## 故障定位

- `/health` 的 `model.configured=false`：检查密钥文件路径与 JSON 格式。支持 `api_key` / `apikey` / `key`，以及 `base_url` / `api_base` / `model`。
- 模型 HTTP 401/403：检查提供商和密钥；HTTP 400：检查模型名及兼容参数；不要复制带密钥的完整请求进聊天或日志。
- 模型超时：本轮没有可靠答复，稍后重试。摘要失败但答复可查看时，界面明确提示“未写入记忆”。
- 来源核对或记忆版本失效：重新执行；不能将失败当作“无指南”。
- 登录后来源被拒绝：部署地址须与 `ALLOWED_ORIGINS` 对应。HTTPS 才启用 Secure Cookie。
- 本地与 Docker 的密码和数据独立，不可混用。重启后登录会话失效，需重新登录。
