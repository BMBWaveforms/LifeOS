# 可替换 Agent 执行层与测试页

本次保留 Python 业务后端，增加 Claude Agent SDK 执行层，继续使用 DeepSeek。测试页用于运行对比；完整质量评测台在下一阶段开发。

## 入口与选择

完整应用首页是产品；同一地址下 `/workbench.html` 是测试台，使用同一套产品账号登录。配置私有 TEST_ACCOUNT_PASSWORD 后提供 test1 到 test10，各账号的产品记忆和测试记录独立。GitHub Pages 不包含真实测试台。

测试按钮选择 Python 自实现 / Claude Agent SDK，只影响测试会话。产品默认由 `AGENT_RUNTIME=native|claude-sdk` 控制，修改后重启后端。SDK 失败明确报错，不自动回退。

Compose 和示例配置默认 claude-sdk；无变量直接启动 Python 时默认 native。`/health` 和登录后的 `/api/runtimes` 返回默认值、安装状态和 SDK 版本。安装状态不证明模型 Key、余额或调用已验收。

## 文件与职责

| 文件 | 职责 |
|---|---|
| `backend/main.py` | 登录、HTTP API、账号级请求锁 |
| `backend/model.py` | 提示词、有效上下文、选择执行层、校验答案、摘要与首页回访 |
| `backend/executors.py` | ExecutionRequest / ExecutionResult 接口；NativeExecutor / ClaudeSDKExecutor |
| `backend/tools.py` | 共用工具注册、参数/账号/revision 校验、调用上限、工具轨迹 |
| `backend/store.py` | 指南检索、来源校验、SQLite 记忆、纠正与删除 |
| `backend/workbench.py` | 隔离测试会话、结果持久化与账号归属检查 |
| `frontend/workbench.html` / `workbench.js` | 执行层切换、续聊、对比、历史与记录下载 |

工具仍是 `search_entries(query)` 和 `get_entry(guide_id)`。声明在 `prompts/tools.json`，注册和调用在 `backend/tools.py`。新增工具需要同时维护函数、声明、权限、提示词和测试；SDK 不代替工具业务逻辑。

摘要和首页是无工具的固定任务，继续通过原 OpenAI-compatible API 调用 DeepSeek。切换问答执行层不会切换模型提供者或这两个任务。

## SDK 配置与约束

锁定 `claude-agent-sdk==0.2.166`，Python 3.10+；Docker/CI 使用 3.12。SDK 包自带平台对应的 Claude Code CLI，宿主机不需另装 Claude Code。

```dotenv
AGENT_RUNTIME=claude-sdk
AGENT_SDK_BASE_URL=https://api.deepseek.com/anthropic
```

SDK 复用原模型配置中的 Key 和模型名。原 base_url 仍用于 Chat Completions；SDK 用独立的 Anthropic 兼容入口。缺省只对 api.deepseek.com 自动映射；其他提供者必须提供真实兼容地址。Key 不写入公开配置或前端。

SDK 内置工具清单为空，不读取用户/项目设置，仅连接注册的指南 MCP 工具。执行前 hook 和权限回调限制工具；启动报告的工具清单也会检查。当前未开放 Bash、文件、Web、Skills 或子 Agent。

指南问答最多 7 次模型轮转、24 次工具执行、180 秒；原生每次模型工具列表另限 12 个调用。两种运行层的轮次统计语义可能不同。工具失败会记录并使整轮结果失效。SDK 的 USD 估算不作为 DeepSeek 真实费用；可查看返回的 token usage。

## 连续会话与删除

第一阶段使用每轮新 SDK 会话，由 Python 重放最近 6 轮已校验问答。SDK 负责本轮工具循环；Python 决定下一轮允许读取哪些历史。关闭 SDK 原始会话写入，不使用 resume / continue 恢复旧上下文。

删除、纠正、记忆开关变化，或执行层、聊天提示词和工具版本变化，会使旧短期历史失效。工具与最终结果仍检查账号、记忆 revision 和本轮真实全文读取。

本次没有启用 SDK 跨请求原生会话恢复，也没有实现产品完整聊天历史持久化或超长聊天自动压缩。未来启用原生恢复前，需先设计身份映射、历史删除和提示词版本失效规则。

测试成功问答单独持久化；后端重启后用同一测试 session_id 可重建最近有效问答。页面刷新后可从运行记录查看结果，点击“续接此测试会话”恢复这个会话的最新进展，也可开始新会话。

## 使用测试页

1. 登录后选择执行层，输入问题，点击“运行本次测试”。首次自动创建隔离会话。
2. 输入下一句话继续。同一执行层续接自己的测试历史与记忆。
3. 切换执行层使用另一个独立会话；“新测试会话”清空当前上下文，保留已有运行记录。
4. “对比两个执行层（新会话）”用相同输入分别新建 native / claude-sdk 会话，顺序执行并并排展示。读取当前提示词文件，记录实际哈希；对比前核对版本是否一致。
5. 展开工具输入输出、摘要变化和运行配置；从历史回看、续接测试会话或下载本轮 JSON。续接使用该会话最新进展，不回滚到旧记录。

对比展示相同业务输入下的实际接入路径表现；两种接口的默认请求参数和上下文包装可能不同。严谨选型需在完整评测台固定模型、版本和参数。

测试数据在运行目录 workbench/，产品记忆在原 memory.sqlite，彼此不复制。每个测试会话有独立数据库，账号只可查看自己的测试结果。记录包括执行层、输入输出、提示词哈希、工具声明哈希、指南版本、工具轨迹、耗时、记忆前后状态；SDK 另有包版本、配置模型和 token usage。不记录 Key、请求头或模型私有思维链。

“执行完成”表示运行和后端校验完成，不代表回答质量通过。评测集、批量质量测试、五环节独立评测、系统评分/人工复核、提示词编辑与发布管理尚未实现。

## API

所有测试接口需要登录 Cookie，owner 来自登录态。

| 接口 | 输入/输出 |
|---|---|
| GET `/api/runtimes` | 产品默认、可用执行层和包版本 |
| POST `/api/test-sessions` | `{runtime,memory_enabled:true}` → session_id |
| POST `/api/test-run` | `{session_id,runtime,query}` → 完整运行记录；失败为 status=error |
| GET `/api/test-runs` | 当前账号最近 30 次运行概要 |
| GET `/api/test-runs/{id}` | 当前账号的一次完整运行记录 |
| POST `/api/run` | 保留原产品 API；chat 可指定 runtime，缺省使用产品默认 |

测试 session 的执行层绑定创建值，不能在旧 session 偷换 runtime。同账号一次运行一条测试，忙时返回 409；产品与测试分别加锁。

## 部署与回切

沿用已有 .env.compose、项目名和数据卷：

```sh
docker compose --env-file .env.compose up -d --build
docker compose --env-file .env.compose ps
```

回切在现有配置设置 AGENT_RUNTIME=native，执行：

```sh
docker compose --env-file .env.compose up -d backend
```

本地修改私有 .env 后重启后端。Python 3.9 环境保留，另建 3.10+ 环境。切换不删除卷、不改 Compose 项目名。

自动测试使用替代 SDK 传输，覆盖来源校验、失败终止、未授权工具、删除后的历史失效、错误脱敏、测试/账号隔离及测试历史恢复。真实模型和 Docker 验收独立记录在 [验收记录](验收记录.md)。
