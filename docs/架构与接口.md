# 架构与接口

## 两个独立服务

```text
浏览器 → 独立前端（本地静态服务 / Docker Nginx）
       → /api 反向代理 → FastAPI Python 后端
                       ├─ 直接 HTTPS 调用模型 API
                       ├─ 固定指南检索与全文回读
                       └─ SQLite 长期记忆与进展记录
```

后端不提供静态页面。前端通过同源 `/api` 请求后端，不持有模型凭据。模型客户端使用 OpenAI 兼容 Chat Completions HTTP 接口；问答执行层另可选择 Claude Agent SDK，使用 DeepSeek 的 Anthropic 兼容入口。身份、上下文、来源校验和记忆仍由 Python 负责，不依赖 Dify。切换与测试见 [执行层与测试台](执行层与测试台.md)。

## 个性化问答

1. 验证登录身份，生成绑定该用户及记忆 revision 的本轮上下文。
2. 按需读取最多 12 条有效长期摘要，加同一会话最近 6 轮已校验的问答。当前输入优先。纠正、删除、开关等操作使旧短期会话失效。
3. 固定当前已启用的提示词组合（三模块合成主提示词），加载 `tools.json`，由 native / claude-sdk 调用共用的指南工具。最多 7 次模型轮转、24 次工具执行；原生每次最多 12 个调用；总预算 180 秒。SDK 每轮新建会话，仅重放已校验历史。
4. 校验结果状态、引用的全文回读记录、用户归属和 revision。引用卡片正文由指南字段生成，模型不能自创正文、收益或来源链接。
5. 开启记忆时调用 `summary.md`，以本轮问题、校验后答案和有效旧摘要生成摘要。验证明确状态的原文依据、解决反馈、父摘要和真实咨询指南后提交事务。
6. 相同问题的新摘要替代旧摘要成为有效记录，旧记录标为 `superseded` 并保留可见。手动纠正会清除旧状态依据，首页只接收当前问题、进展、时间和记录 ID。已解决问题保留咨询经历，退出首页回访。
7. 返回答案与摘要保存状态。摘要失败明确显示“未写入记忆”，不假装成功；记忆管理变更使在途旧结果失效。

记忆关闭时不读取长期摘要、不进行摘要调用、不保存长期反馈。已有摘要仍可查看和删除。没有问题的问候也可形成摘要，但不创造待解决的困扰。

## 首页回访

读取有效摘要中最近且未确认解决的问题，调用 `home.md` 选择记录 ID。后端核对记录并生成两个问题：“现在解决了吗？”和“还需要继续咨询相关指南吗？”。首页结果不包含指南正文或建议，不产生新的对话摘要。

“已经解决”和“还没解决”触发带关联摘要 ID 的新对话，仍由模型总结进展后保存。“继续问相关指南”只预填问题，由用户提交后查询指南。

## 模型输出契约

问答：

```json
{"status":"answer|partial|unsupported|clarification|acknowledged","clarification":"澄清问题或空串","cards":[{"guide_id":"03-01","memory_ids":[]}]}
```

每次最多 3 张真实指南卡片；未回读条目、其他用户记忆、陈旧 revision 都拒绝。工具失败、JSON 失败、模型失败和来源校验失败与“指南无足够支持”分开处理。

自动摘要：

```json
{"summary":"中文摘要","user_state":"本轮明确状态或空串","state_evidence":"本轮原文或空串","problem":"问题主题或空串","problem_status":"unresolved|resolved|unknown","status_evidence":"本轮原文或空串","followup_of":"旧摘要ID或空串","guide_ids":["03-01"]}
```

指南 ID 仅能来自本轮真实答复或父摘要中真实咨询过的条目，后端合并保留全部真实 ID。已解决需有关联旧问题及本轮明确肯定反馈；否定、疑问、不确定表达不能置为已解决。用户仍应检查并纠正模型对摘要语义的理解；原文依据校验不等于完整语义校验。

首页：`{"followups":[{"memory_id":"有效且未解决的摘要ID"}]}`。

## HTTP API

| 方法 / 路径 | 用途 |
|---|---|
| GET `/health` | 进程健康、条目版本、配置是否存在；配置存在不等于模型已成功响应 |
| POST `/api/login` | `{username,password}` 登录，设置 8 小时 HttpOnly SameSite Cookie |
| POST `/api/logout` | 撤销当前会话 |
| GET `/api/me` | 当前用户，无模型密钥或内部 token |
| GET `/api/memories` | 自己的摘要、有效记忆、反馈和 revision |
| POST `/api/memory-action` | settings / correct_summary / delete / clear / feedback |
| POST `/api/run` | `{mode:"chat|home",query,conversation_id,followup_memory_id}` |
| GET `/api/guide-entry?guide_id=03-01` | 登录后查看固定指南完整条目 |
| GET `/api/runtimes` | 可用执行层、包版本与产品默认 |
| POST `/api/test-sessions` | 创建绑定执行层的隔离测试会话 |
| POST `/api/test-run` | 在本账号测试会话中运行并保存记录 |
| GET `/api/test-runs` | 本账号最近测试记录概要 |
| GET `/api/test-runs/{id}` | 本账号的一次完整运行记录 |

无公开摘要写入 API、工具执行 API 或公开获取所有账户 token 的接口。API 请求体最多 20 KB；同用户的模型请求串行执行；模型密钥不进入返回值。错误不透传提供商响应正文或鉴权头。

## 数据与部署约束

- SQLite 持久化摘要、明确状态、咨询指南、进展、时间和父记录，不持久化完整逐字聊天。
- 短期问答、运行 ID、回读集合和登录会话在进程内保存。短期问答保留最近 6 轮及约 1 小时窗口；重启后清空，不影响长期摘要。
- 摘要重复提交幂等；已删除的摘要不会由旧运行重建。用户归属和 revision 均在后端校验。
- 配置私有 TEST_ACCOUNT_PASSWORD 后补齐 test1 到 test10，保留原账号。每个账号使用独立盐的 PBKDF2 哈希验证；运行目录内的凭据文件不进入源码包。初始化仅更新指定测试账号密码，不清空记忆和测试记录。
- 单 worker。扩容前需迁移到共享数据库、会话存储和任务协调系统。
- 提示词由独立模块文档初始化，在工作台保存不可变版本和组合；产品显式启用，测试固定快照，返回版本哈希；指南为 2026-10-12 固定快照，687 条。所有条目保留来源和限制。


完整评测架构、版本数据、隔离策略和新增 API 见 [评测工作台](评测工作台.md)。它继续使用同一 Python 业务服务和受约束指南工具；五环节是观察与判定维度，不是五个 Agent。
