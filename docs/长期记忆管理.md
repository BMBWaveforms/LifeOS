# 长期记忆的检索、主题和来源

本功能基于 SDK 会话分支。SDK 负责一段聊天的历史恢复和压缩；SQLite 负责跨会话的来源、主题与权威状态。记忆容量不是12条，旧版的12条只是每次注入上限。

## 用户看到什么

个人档案默认按主题展示，可展开查看本次表达、来源时间与相关记录。继续聊使用主题当前有效的 memory_id。删除单条来源后重新构建主题，删除整个主题会移除它的全部来源；删除最新记录不会自动把已经取代的旧记录恢复为当前事实。

开启记忆后，新增来源会保存本次用户原话以及本轮真正读过的指南编号，供回溯和整理使用。因此原话也属于长期存储，用户可单条或按主题删除。已有用户、设置、账号和运行数据不在代码交付时改写；新增表在部署启动时以增量方式初始化。

## 每轮如何找回

1. 只在当前账号的有效来源中查找。用户明确选择的回访条目必须保留。
2. 主题及其来源通过中文双字、关键词和有限同义词匹配当前问题；相关性优先，时间作为次级排序。没有匹配时提供近期记录作为兜底。这是轻量词法检索，不声称达到语义检索效果。
3. 按完整记忆数组的 JSON 长度估算预算；默认4096估算tokens、最多32条。估算方式为UTF-8字节数除以2向上取整，不是DeepSeek精确tokenizer，也不是整个请求的窗口预算。系统提示词、指南、SDK历史另占上下文。
4. 不截断单条记忆来凑数量。显式回访单条也放不下时返回清楚的预算错误，不能假装继续了该记忆。

`memory_selection` 返回候选数、选中数、估算长度、预算与截断原因，可在隔离测试轨迹检查；不返回额外私人检索原文。首页按未解决主题回访，已解决问题退出回访。

## 主题自动整理

同一主题按有效的父记录关系延续；只有完全相同且唯一的明确主题才可直接归组，不按模糊相似度强行合并不同问题。源记录保留，主题摘要是可重建派生结果。

同一主题积累到默认8条来源或1200估算tokens时，可在已完成答复后排入后台队列。只有一个整理worker，最多32个待处理主题，同主题任务合并。模型使用已有无工具、无历史恢复的SDK临时任务，最长45秒；模型调用可能增加部署的用量。

整理输入只包含当前仍存在的原始来源，不输入旧累计摘要。模型只选择 `source_id + quote`，每段quote必须在对应来源中连续出现；后端验证账号、主题、来源和引文，最多12段并控制长度。自由改写的模型总结不会直接成为权威事实。保留数字、单位、否定与条件仍需要用实际案例评估，引用存在不能证明语义选择完美。

排队任务向模型发送前、后台结果提交前都会校验用户记忆仍开启、来源指纹及业务revision未改变。已关闭或删除的来源不会从等待队列重新发送；已经发出的模型调用不能追溯取消，返回结果仍须通过提交校验。删除、纠正或新增来源之后，迟到结果不能覆盖新状态。整理缓存不改变业务revision，不因后台整理清理正常SDK续聊。整理失败不影响已经校验的回答，读取仍回退到来源；同一来源指纹的失败重试有上限，不无限重复收费。

固定提示词位于 `prompts/memory-consolidation.md`，内容哈希随缓存保存。它是只做证据摘录的维护任务，不代替工作台中的七模块产品提示词。自由测试和批量评测默认不启动未记录的后台模型调用；要评估整理本身，使用独立用例及显式后台等待，不能将其耗时/用量混进既有A/B。

## 删除、纠正和旧数据

删除来源、主题或全部记忆时，在同一事务内清理来源及派生缓存并提升revision，沿用现有SDK历史失效机制。模型不得从后代累计摘要中重新捡回已删事实。纠正记录后，原表达不再作为有效检索/整理证据。源指南编号来自每轮实际读取集合，不从模型摘要继承编造。

旧数据库没有保存完整用户原话时，只使用已保存的明确原文证据并标识历史来源限制；不把模型累计摘要伪装成用户原话，也不从SDK私有transcript导入原始记录。原有累计摘要可能含已删来源，不能作为新证据层。回退代码前备份运行卷；回退只能回到仍尊重这些来源/删除规则的兼容版本，不能把旧累计文本重新作为权威来源。

## 配置

| 环境变量 | 默认值 | 用途 |
|---|---|---|
| MEMORY_CONTEXT_TOKENS | 4096 | 本轮记忆数组的估算预算 |
| MEMORY_CONTEXT_MAX_ITEMS | 32 | 记忆数组的额外条数上限 |
| MEMORY_CONSOLIDATION_ENABLED | true | 产品端后台整理开关 |
| MEMORY_CONSOLIDATE_SOURCES | 8 | 按主题来源条数触发 |
| MEMORY_CONSOLIDATE_TOKENS | 1200 | 按主题来源估算长度触发 |

这些是可调整的初始参数，不是质量基准。先验证旧但相关的来源能否找回、更新后的条件是否优先、删除后是否复活，再比较长度、耗时与用量。
